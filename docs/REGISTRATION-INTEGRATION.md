# Google Sheets registration adapter (prepared, not deployed)

This replacement has **not been deployed or connected to the public form**. Existing endpoint and public configuration remain unchanged. Mocked tests cannot establish live persistence. The source has been saved in the owner-private staging Apps Script project https://script.google.com/home/projects/1-4rQ1RO88jiBfmNCraeyVv1oTZYSFnrkvvZQwUtWlNMfBZUtT2x7ImBG/edit and verified exactly against the generated bundle. An authorized Google owner must authorize/deploy this Apps Script, approve spreadsheet access, and supply server secrets before a controlled live test. Supabase deployment access is also required. No credentials are stored in this repository.

## Destination and design

The sole destination is spreadsheet `1q4K_eLaJj_sRhzFWi0rwvVjGn7jqjDCL0BWRPLF3WDM`, tab `Registrations`, with exactly these columns:

`id,email,role,interested_in_pilot,contact_consent,consent_timestamp,privacy_notice_version,preferred_language,created_at,status`

Browser → Supabase Edge proxy → owner-authorized Apps Script → Sheets. The Apps Script web app is network reachable (Google's web-app setting permits anonymous transport); a high-entropy server secret authenticates every request. It is **not** an unauthenticated write endpoint or a Google-private HTTP deployment. The browser never receives this secret, Google credentials, or the adapter URL. Google credentials stay within the owner's Apps Script authorization. Do not publish generated Code.gs or include backend files in static hosting.

The script holds one cross-request ScriptLock while reading headers, updating persistent rate counters, checking normalized emails, appending and flushing. All writers must use this single deployment/script project; two independent projects or manual concurrent imports bypass this lock. Duplicates return the same success response without changing prior consent evidence. Server time supplies both consent and creation timestamps. Formula-like text is escaped before write. Neither request/record contents nor secrets are logged.

Per normalized email: five requests per UTC hour. Global: 500 attempts per UTC hour. Counters live in Script Properties, survive requests, use HMAC email keys, and expired keys are removed on subsequent requests. The global cap also bounds rotating-email attacks, but can cause temporary shared unavailability. Origin checks limit browser use; origins can be spoofed by non-browser clients. These controls do not replace an upstream WAF for high-volume abuse. Consent and adult parent/teacher roles are validated at both layers. Request bodies are bounded to 4096 bytes with a five-second read deadline at the proxy; adapter envelopes are bounded and expire after 60 seconds. Retries are duplicate-safe; a network timeout after an append may show an error even though the row exists.

## Owner deployment

1. Confirm the destination owner, sharing permissions, privacy notice version, retention period, and permitted website origins. Limit spreadsheet and script editors to authorized operators. The sheet contains personal information; avoid public link sharing.
2. Run `node backend/bundle-apps-script.js`. The generated `work/apps-script/Code.gs` is already saved in the staging project above. Reuse that project; do not create a second independent adapter project. Confirm the V8 runtime. Do not run it as a browser script.
3. In Script Properties, set `ADAPTER_SECRET` to a cryptographically random secret of at least 32 characters, `PRIVACY_NOTICE_VERSION` to the approved public version, and `REGISTRATION_ENABLED` to `true`. Keep the secret in a password manager and server configuration only.
4. Deploy a web app executing as the authorized spreadsheet owner, with transport access allowing the Edge proxy to call it. Complete Google's authorization for Sheets. Copy its `/exec` URL into the Edge secret `SHEETS_ADAPTER_URL`. If organizational policy disallows this web-app access, use an authenticated Cloud Run service with a service account instead; do not weaken the secret gate.
5. Deploy `backend/index.ts`, `backend/sheets-proxy.js`, and `backend/sheets-core.js` together as a Supabase Edge function. For a public form, its platform JWT requirement must be disabled; the handler performs origin and payload checks. Set Edge-only `ADAPTER_SECRET`, `SHEETS_ADAPTER_URL`, `ALLOWED_ORIGINS` (comma separated exact HTTPS origins), `PRIVACY_NOTICE_VERSION`, `PRIVACY_READY=true`, and `REAL_SIGNUP_ENABLED=true`. The public privacy document and approved notice must already be available. Exclude `backend/` and `work/` from frontend artifacts.
6. Before changing the live `signup` deployment, test on a staging Edge function using an authorized operator's consent and synthetic email. Confirm exactly one literal row for repeated submissions, two server timestamps, all ten columns, allowed-origin preflight, denied origin, invalid consent rejection, and private sheet visibility. Delete the synthetic row after verification. Test adapter lock/rate cases with mocks; do not generate bulk live registrations.
7. Only after these checks, replace the existing Edge `signup` function using this implementation so the frontend contract and configured URL remain compatible. Keep the previous deployment available for rollback. Document the real deployment/version and verification outcome. Do not switch back to another store silently: disable collection if confirmed Sheets storage is unavailable.

The existing Supabase registrations are not automatically exported by this implementation. Historical export/migration needs an authorized read and a separately reviewed deduplicated import, preserving original consent timestamps. Do not fabricate consent for legacy rows.

## Erasure and operational limits

Verify the requester's identity through an authorized channel; do not expose a public email lookup or deletion endpoint. An authorized operator should temporarily disable `REGISTRATION_ENABLED`, locate all normalized-email matches in Registrations (including escaped literal forms), delete the complete rows, and check any authorized exports/backups against the retention policy. Remove the corresponding `RATE_<HMAC>` Script Property if immediate rate-state erasure is needed; otherwise it expires at the next UTC hour and is cleaned on the next accepted request. Re-enable only after verification. Record completion without retaining the erased email in this repository. Deleting a row makes future consensual re-registration possible. Sheets version history and Google backup retention require the owner's administrative retention policy; row deletion does not promise removal from Google's historical copies.

Apps Script quotas, the sheet's growing linear duplicate scan, and Google's service availability limit this lightweight integration. Monitor owner quota/errors without logging payloads. At higher volumes move the uniqueness/rate transaction to a database and mirror to Sheets. Changing Apps Script code requires publishing a new deployment version. Rotating secrets must update both server locations, with collection briefly disabled to avoid mismatches.
